差异：

- **1.1 对象模型与层级**：两边都没有「Trace 即一行」。coze-loop 以 span 表为准，Langfuse v4 以 events_full 为准。旧版 Langfuse 另有独立 traces 表。
- **1.2 类型与状态**：Langfuse 的状态是四级 level，coze-loop 只有成功和失败。
- **1.3 Token 用量**：coze-loop 只收 SDK 上报的 token。Langfuse 可在缺失时本地补算。
- **1.4 金额成本与价格表**：最大的单项差距。coze-loop 要做金额统计，必须新增单价配置和计价逻辑。

推断（不是源码直接写明的事实）：

- **【推断】** coze-loop。产品里的一条 Trace 是同一 trace_id 下 span 的查询视图，存储层没有独立 Trace 行。依据：DDL 和 GetTrace。
- **【推断】** coze-loop。要做金额成本统计，需要新增模型单价配置和计价逻辑。依据：现有只有 token 汇总，没有金额字段。
- **【推断】** Langfuse。「Trace」在 v4 里是 events_full 行按 trace_id 聚合出来的视图，不是一张表。依据：Postgres 无 Trace 表，is_app_root 和 trace_name 在 events_full。
